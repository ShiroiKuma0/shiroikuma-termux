# Changelog

This file carries the history of **白い熊 Termux** — 白い熊's fork of [Termux](https://github.com/termux/termux-app) — newest first. Upstream ships no `CHANGELOG.md` (its history is its GitHub release notes), so this file is the fork's alone; should upstream ever add one, it goes below this block untouched. Built-and-signed APKs are on the [Releases page](https://github.com/ShiroiKuma0/shiroikuma-termux/releases). The app keeps the id `com.termux` and installs **over** the stock Termux, signed with the one key of the whole `com.termux` shared-UID family.

Versions are `<upstream version>+<upstream base date>.<HH-MM>.g<sha8>+<NNN>`: `custom` is rebased onto every commit of upstream's `master`, and the pin names the upstream commit the release is built on; `versionCode` = upstream code × 10000 + N. Every release section states its upstream base, then what is built on top of stock; sections after the first are per-release deltas and carry an "Upstream since" subsection distilled from the sync(s) that moved the base.

## 白い熊 Termux 0.118.0+2026-09-11.22-27.g45844885+008 — 2026-09-13

Built on the same upstream base as +006 — **termux/termux-app `master` at [`45844885`](https://github.com/termux/termux-app/commit/4584488513c099f2e98bcfcd00f006d213248729)** (no sync since; no upstream changes to report). `versionCode 1180008`. Changes since +006:

### UI & theming
- **Text-selection toolbar in the house look.** The COPY · PASTE · MORE… bar over a selection is now our own `ShiroikumaSelectionToolbar` — a black bar with yellow text and border, following the Menus rows of the UI page (`menu_bg`, `menu_text`, `menu_border_color`, `menu_border_dp`, `menu_corner_dp`) — instead of the platform floating toolbar, which cannot be themed (it re-wraps the window context in `Theme.DeviceDefault` and takes only light/dark from the app). It behaves as before: hides while a handle is dragged, follows the selection as it moves or scrolls, sits above the selection when there is room and below it otherwise, never under the keyboard; PASTE is dimmed while the clipboard is empty. Implemented as an `ActionMode` of ours over a non-focusable `PopupWindow` one window layer above the selection handles, installed through a small factory seam in `terminal-view`'s `TextSelectionCursorController` (`setFloatingActionModeFactory`), so upstream's selection logic is untouched.
- **Settings screens in yellow.** Every activity except the terminal one — Settings and all its sub-screens, Help, About / Report, the widget's shortcut picker, the float permission page — now receives `ThemeOverlay.Shiroikuma.Secondary` from `ShiroikumaLifecycle`: pure black ground (was Material's dark grey), yellow titles, dim-yellow summaries, yellow switches and category headings.
- **「Show side menu」** is the first row of the terminal's context menu (the one MORE… opens, also reached by a right-click or the menu key): it opens the left sessions drawer, so the drawer no longer depends on an edge swipe that gesture navigation fights over.

### Build pipeline
- **Our `termux-shared` for the sister forks.** `./gradlew publishReleasePublicationToMavenLocal` now publishes this repo's `termux-shared` (+ `terminal-view`, `terminal-emulator`) to `~/.m2` as `com.termux:termux-shared:0.118.0-sk1` — 白い熊 names and links in `TermuxConstants`, the absorbed-plugin preference lookups — for shiroikuma-termux-api to build against instead of upstream's JitPack artifact. A one-line `apply from: 'shiroikuma.gradle'` at the end of each of the three library modules re-labels upstream's `release` publication to `SHIROIKUMA_TERMUX_SHARED_VERSION` (`gradle.properties`); upstream's literal `0.118.0` stays untouched.
- Docs: the bundled colour-scheme count corrected to 114 + the house scheme; the sync skill's post-rebase checklist gained the `terminal-view` seam.

## 白い熊 Termux 0.118.0+2026-09-11.22-27.g45844885+006 — 2026-09-13

First release. Built on **termux/termux-app `master` at [`45844885`](https://github.com/termux/termux-app/commit/4584488513c099f2e98bcfcd00f006d213248729)** (committed 2026-09-11 22:27 UTC / 2026-09-12 local; upstream `versionCode 118` / `versionName 0.118.0`, months past the 0.118.x store releases — Sixel/iTerm images, the 100 KB OSC 52 clipboard buffer, the multi-window margin flicker fix are all in). `versionCode 1180006`. Everything below is added on top of upstream.

### Major features
- **白い熊 Termux UI page** (`com.termux.shiroikuma.ui.ShiroikumaUiActivity`) — one page for the whole look of the app, opened by a long-press on the drawer's gear, from the terminal context menu (upstream's *Style* slot, relabelled), from the first row of the Settings root screen, and from a static launcher shortcut. Translucent over the terminal so every change **previews live** through upstream's `ACTION_RELOAD_STYLE` path (throttled to one reload per 80 ms).
- **Export / Import** of the whole installation — settings plus `home` and `usr` as tar entries inside one zip — with a restore that swaps the trees in atomically and works into a fresh install before its first launch.
- **Sister-app backup-automation contract v2** — exported receiver, gate, provider data door, progress broadcasts and a foreground service, so 保存復元 (shiroikuma-jiyusagyoban) can back the app up unattended.
- **Termux:Boot, Termux:Widget and Termux:Float absorbed** into the app as `com.termux.boot`, `com.termux.widget` and `com.termux.window`; **Termux:Styling absorbed** into the UI page (its colour schemes and fonts bundled). No plugin APKs, no second launcher icon.
- **Fork identity**: the name 白い熊 Termux, the black-and-yellow traced icon, our links; app id, namespace and `sharedUserId` stay `com.termux`.

### UI & theming (白い熊 Termux UI)
- House look throughout the page: black/yellow palette, a 36/54/72/90 dp size ladder, text-wide underlined section headings, 5 dp rows, pill buttons, chain-closing dialogs (`ShiroikumaDialogs`, `ShiroikumaPreference`, `ShiroikumaSeekBarPreference`, `ShiroikumaTheme`, `preference_*shiroikuma*` layouts, `shiroikuma_{dialog,pill}_bg` drawables).
- **Terminal section** — a live sample row; Background / Foreground / Cursor colour pickers (`ShiroikumaColorPicker`: four ARGB sliders, alpha disabled for terminal colours, recent-colour swatches kept in `recent_colors`), written as `key=#RRGGBB` lines to `~/.termux/colors.properties` by `TerminalStyleFiles`; **Colour scheme…** picker (`ShiroikumaSchemePicker`) over the 114 termux-styling schemes plus the house `shiroikuma.properties`, bundled under `assets/shiroikuma/colors/`; **Font** picker (`ShiroikumaFontPicker`, each entry drawn in its own glyphs) over the bundled Cascadia Code, Fantasque Sans Mono, Fira Code and Meslo (OFL/Apache, licence texts beside them) plus `~/.termux/fonts/*.ttf|otf`, with *Add font…* importing a file through the system picker; the chosen font is copied to `~/.termux/font.ttf`; **Font size** slider (`TermuxAppSharedPreferences.setFontSize`).
- **Extra keys row** — `extrakeys_bg`, `extrakeys_text`, `extrakeys_active_text`, `extrakeys_active_bg`, text size, border width/colour, corner radius — applied via `ExtraKeysView.setButtonColors` and an `OnHierarchyChangeListener` that styles each `MaterialButton` as `reload()` adds it (`ShiroikumaChrome.applyExtraKeys`).
- **Drawer / sessions** — drawer background, drawer button text, icon tint, session text, selected-session background, dead-session text, session text size (`ShiroikumaChrome.styleSessionRow` from `TermuxSessionsListViewController`).
- **Toolbar / status bar** — toolbar background/text/icon, status-bar and navigation-bar colours for Settings, Help, Report and the UI page, applied by `ShiroikumaLifecycle` (an `ActivityLifecycleCallbacks` installed in `TermuxApplication.onCreate`); the terminal activity keeps upstream's translucent bars.
- **Dialogs / menus** — background, text, title, button, border colour/width, corner radius for our own dialogs; menu background, text, border and corners for the terminal's long-press context menu, which is now our own styled `ShiroikumaContextMenu` hosted by a `TermuxActivityRootView` subclass (`ShiroikumaRootView`, the root class of `activity_termux.xml`); upstream's platform `AlertDialog`s receive the static black/yellow `ThemeOverlay.Shiroikuma.Dialog.Platform`.
- **Widget section** — widget background, text and text size (10–24 sp), pushed to every placed widget's `RemoteViews` (debounced 150 ms); actions *Refresh widgets*, *Create dynamic shortcuts*, *Remove dynamic shortcuts*.
- **Floating terminal section** — *Open floating terminal*; frame background, border colour, border width (0–4 dp), corner radius (0–24 dp) and the notification text; a running window restyles live through `TermuxFloatService.reloadStyle()`.
- Long-press on any colour or size row restores the house default (an absent key = default); **Reset** (confirmed) clears the `shiroikuma_ui` preferences, rewrites the house `colors.properties`, deletes `font.ttf`, restores the default font size, reloads and recreates, and refreshes the widgets and the floating window.
- `ShiroikumaDefaults` writes the house `colors.properties` once on first run when none exists (marker `defaults_written`).
- The page's `onResume` fires one extra reload, since an opaque system picker may have stopped the terminal activity in between.

### Backup & automation
- **Export / Import panel** (`ExportImportPanel`, a port of raikidoban's): one bordered box, the export directory shown in yellow (red when unset), the last-backup line, an all-select checkbox and per-category checkboxes with *Home* and *Packages* indented under *Data*, pill buttons *Cancel* ‖ *Import* *Export*, a progress line while a run is in flight (Cancel stops the job). Success opens an info dialog whose OK closes the chain — dialog, panel, page; failures leave the panel open; an import ends with *Later* / *Restart now* (`makeRestartActivityTask` + `Runtime.exit(0)`). Before a data export the panel prompts when the app is not battery-exempt; before a `data.*` restore it warns that restoring packages closes all terminal sessions.
- **Export directory** row: an absolute path, chosen with the system tree picker and resolved to `/storage/emulated/0/…` or `/storage/XXXX-XXXX/…` (`ExportDir`); a red second line "All-files access not granted — tap to grant" while `MANAGE_EXTERNAL_STORAGE` is missing on API 30+ (tap opens the grant page; long-press always opens the picker). **Last export** row shows the newest `shiroikuma-termux_*.zip`, queried on a background thread on every resume.
- **Archive** `shiroikuma-termux_<yyyy-MM-dd_HH-mm-ss>.zip`, written as `.part` and renamed (`TermuxBackup`, Apache Commons Compress 1.27.1, Zip64 always, `manifest.json` first): `manifest.json` (format `shiroikuma-termux` v1, app version, timestamp, categories, per-tree byte totals), `settings.json` (typed dump of `com.termux_preferences` minus `current_session`, and `shiroikuma_ui`; `PrefsJson`), `settings/termux.properties`, `settings/config/termux.properties`, `settings/colors.properties`, `settings/font.ttf`, `settings/fonts/*`, `data/home.tar`, `data/usr.tar`.
- **Categories** (`TermuxBackup.Cat`, all on by default): `settings` — Settings (app preferences · termux.properties · colours · font); `data` — Data (home + packages); `data.home` — Home (`/data/data/com.termux/files/home`); `data.usr` — Packages (`$PREFIX` = `files/usr`). `data` alone means both parts.
- **Tars in Java** (`TarPack`): POSIX long names and big numbers, entries from `Os.lstat` (mode, uid/gid, mtime), directories, regular files (a file that shrinks under the walk is zero-padded, one that grows is cut, an unreadable one skipped), symlinks via `Os.readlink`, hard links through an inode map, sockets/FIFOs/devices skipped and counted; a pre-walk gives honest totals; stored at DEFLATE level 0 so `unzip -p x.zip data/home.tar | tar t` streams. Requires API 26+ for the data categories (`TermuxBackup.supported()` refuses below that with a clear error).
- **Restore** (`TermuxBackup.importZip`, streaming, no spool): settings merge with `commit()` and the files are copied; **tighten-only rule** — `allow-external-apps=true` from an archive is written as `false` unless the device already had it on (also post-passed over the restored home's two properties files), and the summary says so. `data.*` unpack into `files/home-staging` / `files/usr-staging` (`TarUnpack`: path-traversal guarded, modes via `chmod` with directories last, mtimes, symlinks, hard links); only after the LAST byte of the zip has been read does `ProcessReaper` stop `TermuxService` (`ACTION_STOP_SERVICE`) and SIGKILL every other process of the UID from `/proc` (sparing itself — note the shared UID: Termux API / X11 / GUI / Emacs processes die too), then the trees swap `live → live.old`, `staging → live`, `.old` deleted. Free-space check up front from `manifest.bytes` (+5 % + 64 MB) → `ERROR:not enough space (need X, have Y)`; a truncated archive never touches live data; cancel deletes staging. Because upstream's installer skips the bootstrap when `$PREFIX` exists and is non-empty, a restore before first launch boots into the restored prefix (`describe` reports `requires_launch_first:false`).
- **§1 `StateExportReceiver`** (exported, no permission): `com.termux.action.EXPORT_STATE` / `LIST_CATEGORIES` / `CANCEL_EXPORT`; extras `token`, `path` (absolute directory, wins over the configured one; `ERROR:no-storage-access` without the grant, `ERROR:no-directory` when neither is set), `items`, `progress_action`, `reply_action` / `reply_package` / `reply_id`. The receiver only gates, validates and starts the service (guarded `startForegroundService`; `ERROR:no-foreground-start` when not battery-exempt, else `ERROR:cannot start export service: <Class>`). Exactly one reply broadcast per request, sent with `FLAG_INCLUDE_STOPPED_PACKAGES` and `reply_id` echoed: `OK:<abs path>|<bytes>|<human>|<n> categories`, `OK:` + `id\tlabel\tparent\ton|off` lines, or `ERROR:<reason>` (`automation disabled`, `bad token`, `export already running`, `cancelled`, …). `CANCEL_EXPORT` is silent; the export unwinds at the next entry, deletes its `.part` and answers its original request `ERROR:cancelled`.
- **§2 `AutomationAuth`** (`shiroikuma_automation` preferences, device-local, never exported): `automation_enabled` (default on), `automation_require_token` (default off), `automation_token` (24 SecureRandom bytes as hex, minted lazily; compared with `MessageDigest.isEqual`). On the UI page: the *Automation export* switch, *Use authorization token?*, and a token row (`AutomationTokenPreference`) visible only while a token is required — tap copies it, *Regenerate* rotates it after a confirmation.
- **§2a `AutomationProvider`**, authority `com.termux.automation`, exported: `describe` (contract/format headers from the manifest, `requires_launch_first:false`, `requires_permissions:[]`, `contains:["Settings","Home (~)","Packages ($PREFIX)"]`), `export` / `import` over a `dup()`ed file descriptor (the callee mints the `job_id`, returns `OK:<job_id>`, and every progress line and the terminal reply carry it), `cancel`. Callers verified by exact package name → uid → pinned certificate (`AutomationCallers`: `shiroikuma.oyokanri`, `shiroikuma.jiyusagyoban`); `import` exists only here.
- **§3 `AutomationProgress`**: lines at most every 500 ms, the final line always, a 20 s heartbeat; `item` = category id, `text` like "Home 1234/8942 · 512 MB / 4.2 GB", `current` / `total` files, `unit` "files", `bytes` / `bytes_total`.
- **`AutomationDataService`** (`foregroundServiceType="dataSync"`, unexported, partial wakelock, notification channel `shiroikuma_backup` with progress in the notification text): every run — the panel's too — executes here, so one engine has one runner; modes file export (§1 + panel), descriptor export (§2a), descriptor import (§2a + panel); a stale job id stops silently; the panel follows its job through `AutomationJobs.Listener`.
- **Manifest**: `<queries>` for both callers, `FOREGROUND_SERVICE_DATA_SYNC`, the receiver / provider / service, and the integer `<meta-data>` `shiroikuma.automation.contract`=2, `.format`=1, `.min_format`=1.

### Build pipeline
- `app/shiroikuma.gradle`, applied by the last line of `app/build.gradle` (after upstream's inline SemVer `validateVersionName`, which allows only one `+`): reads upstream's untouched `versionCode 118` / `versionName "0.118.0"` and overwrites them with `versionName = "<upstream>+<base date>.<HH-MM>.g<sha8>+<NNN>"` (the pin = `git merge-base HEAD master`, its committer time in UTC, resolved through `providers.exec` so the configuration cache re-resolves it) and `versionCode = <upstream code> * 10000 + N`.
- `BUILD_NUMBER` and `LAST_BUILT_VERSION_CODE` in `gradle.properties`; the counter runs monotonically and is reset only when upstream's own `versionCode` moves.
- The `buildFork` task: `assembleRelease` (R8, signed from the gitignored `keystore.properties` — the one keystore of the whole `com.termux` family), copies the universal APK to `~/tmp/shiroikuma-termux_<versionName>_universal.apk`, bumps `BUILD_NUMBER`, records the versionCode it shipped; refuses from the task graph, before the long native build, when `keystore.properties` is missing or the versionCode would not exceed the last built one.
- `buildNdkBuild*` tasks made to depend on upstream's `downloadBootstraps` (the bootstrap zips are `.incbin`ed and must exist before the native build). Universal APKs only (`TERMUX_SPLIT_APKS_FOR_RELEASE_BUILDS` never set); `TERMUX_PACKAGE_VARIANT` at upstream's `apt-android-7`.
- `.gitignore`: `keystore.properties`, `*.jks`, `settings.local.json`, `.scratch/`; `keystore.properties_sample` documents the four keys. Apache Commons Compress 1.27.1, reactive-streams and rxjava declared in `app/shiroikuma.gradle`; `-dontwarn` rules for Compress's optional codecs in `app/proguard-rules.pro`.
- Repo docs for the fork's agents: `CLAUDE.md`, `.claude/skills/build-apk/SKILL.md`, `.claude/skills/upstream-new-version/SKILL.md` (proceed-gated upstream-changes tables for termux-app and for the absorbed plugins).
